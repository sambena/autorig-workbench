Overview & Architecture

Autorig Workbench is an automated rigging, skinning, QA auditing, and animation authoring pipeline for 3D sculpts, generative models, and custom assets. Blender runs completely headless in the background—no Blender window ever opens. Everything is orchestrated through a local web server (Python standard library only) and audited with automated mathematical checks.

Non-Destructive Principle: Source models (FBX, GLB, glTF, OBJ) are never modified. Generated files land cleanly in a rigged/ directory beside the source, accompanied by clips/, and an engine-ready model card model.json.

Pipeline Architecture & Dataflow

Quick Start: Step-by-Step Flow

  1. Add your model: Drop an FBX (with its texture folder), GLB, OBJ, or zip into the drop area on the left panel, or paste filesystem paths.
  2. Survey: Click Survey. Read the 4 facing views under the Survey tab to determine which axis is the front of the model (e.g., [0, -1, 0]).
  3. Edit spec: Click Edit spec to open the 3D editor. Click Suggest skeleton for an automatic proposal, or click joints directly on the 3D model. Click Save.
  4. Run all: Press Run all. The pipeline builds the armature, skins the geometry, enforces envelope capsules, decimates to budget, performs QA audits, authors animations, and creates the preview GLB.
  5. Inspect: Check the audit verdict (PASS, CHECK, or FAIL) and press View results to scrub through clips and inspect weights in the 3D results viewer.

Interactive Button & Action Reference

Every button on the workbench controls an isolated, reproducible script. When a button is disabled, hovering over it reveals the exact prerequisite needed (e.g. "no rig yet: run Rig").

spec_editor.html
Opens the WebGL 3D Spec Editor. Displays the source model with its bone hierarchy drawn in 3D. Allows picking bones for head, hips, limbs, dragging and dropping points in 3D (with Shift snapping), and toggling labels and height/span guide overlays (via the names/guides toolbar checkboxes or the show labels checkboxes next to the Heights and Spans sections) to keep the viewport clean when picking.
Prerequisite: Source model present.
survey.py · facing.py
Surveys what the source model contains: mesh topology, vertex/face count, bounding box measurements, and whether it carries an existing skeleton (Tripo, Mixamo, custom, or none). Renders 4 orthographic facing views (+X, -X, +Y, -Y) so you can unambiguously configure forward.
Prerequisite: Source model file (.fbx, .glb, .obj).
rerig.py / rerig_humanoid.py
Constructs the target armature oriented along canonical game coordinates (facing -Y, feet on Z=0, left on +X). Generates IK foot controls on all legs, skins mesh via bone heat (with watertight voxel proxy fallback for sculpts), applies Torso Envelope & Capsule rules (A-F), and outputs <model>.blend, <model>.fbx, and the QA bend test render.
Prerequisite: Source model and valid rig.json.
decimate.py
Decimates the rigged mesh to the game triangle budget (e.g. 2000 tris). Clamps bone influences to at most 4 per vertex (required by game engine GPU skinning shaders) and normalizes weights. Preserves planar faces and purposefully severed seam boundaries (such as wing membranes from body flanks).
Prerequisite: Rigged .blend or source.
audit.py
Runs rigorous QA checks on the exported game FBX: checks for skin tearing in extreme poses (combined pose & single joint 40° bends), calculates maximum gap %, weight bleed % across unrelated bones, head surface share, and 4-influence limits. Produces _skin.png (bone ownership) and _bend.png (pose stress test).
Prerequisite: Rigged FBX file.
auto_tune.py
Closed-loop self-healing rig optimizer. Parses QA audit results (tear sites, worst bones, gaps, bleed), formulates candidate parameter micro-adjustments (joint blend radii, weight smoothing, capsule scale, station placement, rip welds), and iterates over 3 cycles to eliminate tears and achieve a clean PASS.
Prerequisite: Source model or initial rig. Available via CLI: python autorig/cli/run.py auto-tune <model>
make_clips.py
Procedurally generates animation clips tailored to the model's archetype (e.g. walker: idle, walk, run, bite/attack, hit, death). Measures mesh floor contact frame-by-frame during collapse animations to ensure dead models rest flush against the floor without clipping.
Prerequisite: Rigged model + clips.archetype in rig.json.
publish.py
Generates the official model.json card for game engine asset importers: real-world meters scale, polygon counts, bone lists, animation manifest, and audit certificate. Updates the collection's master pack.json.
Prerequisite: Rigged FBX file.
preview_glb.py
Bakes the skinned mesh, armature, and all animation clips into a compact preview.glb and preview.json. This file powers the interactive 3D Results Viewer.
Prerequisite: Rigged .blend or FBX.
Chained execution
Executes the entire end-to-end pipeline in order: Survey → Rig → Trim → Audit → Clips → Publish → Preview. Streams live terminal logs to the interface and enables cancellation at any time.
Prerequisite: Source model and rig.json.
viewer.html
Launches the interactive 3D WebGL viewer. Allows 360° orbit, playing and scrubbing clips frame-by-frame, toggling bone weight heatmaps, visualizing bleed percentages, and clicking tear sites in 3D space.
Prerequisite: preview.glb generated.
Process Isolation
Immediately halts the active background task. Kills only that specific Blender subprocess by its individual PID without killing any other tasks, terminating the server, or corrupting other models.
Active while any job is in progress.
System Explorer
Invokes your operating system's native file explorer (Windows Explorer, macOS Finder, or Linux xdg-open) directly on the model's generated folder holding its rigged/ files, clips, and cards.
Any model folder.

Bone Placement & Coordinate System

In Autorig Workbench, all 3D positions in rig.json (joint coordinates, cut lines, envelopes) are expressed as normalized [x, y, z] fractions from 0.0 to 1.0 of the model's bounding box after turning to face canonical -Y.

Normalized Coordinate Conventions

Axis Value = 0.0 Center = 0.5 Value = 1.0 Rig Interpretation
X (Span) Model's Right (-X side) Centerline / Spine plane Model's Left (+X side) Limbs on +X are mirrored to -X with .L → .R suffixes
Y (Depth) Snout / Nose / Front Face Mid-body / Ribcage Tail / Rump / Rear Rig faces -Y. Head points towards 0.0, Tail towards 1.0
Z (Height) Ground / Soles of Feet Waist / Knees Crown of head / Top of crest Walkers stand planted on Z = 0; Swimmers/Flyers centered on Z = 0.5

Bone Placement Workflows

Depending on the kind of 3D asset you have, Autorig Workbench provides three primary ways to place bones:

1. One-Click Heuristic: "Suggest skeleton"
In spec_editor.html, clicking Suggest skeleton analyzes geodesic extremities, detects symmetry across X=0.5, aligns spine stations to shoulder and hip hinges, anchors limbs via volumetric surface junctions (Rule C), attaches limbs to nearest body bones (parent_nearest), and generates head_line / head_to_snout (Rule A).
2. Direct 3D Drag & Drop on Points
In the 3D viewport, hover over any chain point (limb tips, bases, spine stations, tube points, head line, jaw) to see it highlight in vivid gold with a grab cursor. Click and drag to reposition the point in 3D in real time. Hold Shift to snap to the centerline ($X=0.5$) or ground ($Z=0.0$). Full Undo (Ctrl+Z) is supported.
3. Click-to-Place (Through the Middle)
For boneless sculpts: check points in the middle in the 3D editor. When you click on a limb or torso in the 3D view, the tool shoots a raycast straight through the model, finds both the front and back entry/exit points, and places the joint exactly halfway through the anatomical interior!
4. Re-Root Existing Generator Bones
For AI-generated models with raw skeletons (such as Tripo bone_0..N): click a bone in 3D to identify it, then click Head, Hips, Leg, or Mirror to convert tangled generator bones into a proper named hierarchy.
5. Cross-Section Pinch Crease Analysis
Analyzes 2D orthogonal cross-sections along limbs and body axes to detect localized narrowing (anatomical pinches). Knees, elbows, and waists snap automatically to the true physical bend creases rather than relying on arbitrary percentage heights.
6. Volumetric Medial-Axis Centerline
Traces curved spines, tails, and tentacles through the 3D interior volume using radial boundary distance balancing. Bones remain centered deep within fleshy volumes, immune to distortion from dorsal fins, pauldrons, or armor plates.
7. Real-Time Symmetry & Mirror Mode
Toggle mirror .L/.R in the viewport overlay: dragging any station on a .L chain instantly reflects across the $X=0.5$ symmetry plane onto the corresponding .R chain in real time, cutting manual adjustment time in half.
8. Live Joint Bend & Pose Test
Toggle bend test in the viewport overlay: pick any chain (e.g. leg.L, arm.L) and scrub the bend slider from $-90^\circ$ to $+90^\circ$. Instantly preview how the skin deforms around the hinge pivot in real time Three.js before triggering Blender.

Rig Kinds & Specifications

The "kind" property in rig.json selects which builder algorithm creates the armature:

Kind Ideal For Key Fields in rig.json How Bones Are Formed
tripo AI generator exports that include raw bone_N armatures head, hips, chains, legs, delete, mirror Reuses joint positions, strips messy parenting, re-roots at hips, and cleans rolls.
build Boneless sculpts, animals, creatures, machines, serpentine forms chains: [ {slice: [y0, y1]}, {tip: [x,y,z]}, {tube: [s, e]} ] Traces cross-sectional centroid slices for spines, tubes for necks/tails, and tips for limbs.
placed Complex creatures with wings, membranes, armor plates, and jaw articulations parts, blends, rip_welds, membranes, rigid_islands Hand-placed chains reinforced with boundary rules that prevent cross-bleed between adjacent anatomical parts.
humanoid Human figures, knights, bipedal humanoids hip, knee, ankle, spine, neck, shoulder, wrist heights/spans Standard game humanoid rig (compatible with Mixamo/Unreal/Unity retargeting) measured from frontal proportions.

Example: Constructive Build Chains

{
  "schema": "autorig-spec/1",
  "rig": {
    "kind": "build",
    "forward": [0, -1, 0],
    "skeleton": "quadruped",
    "chains": [
      { "name": "spine", "slice": [0.25, 0.75], "bones": 3, "names": ["hips", "spine", "chest"] },
      { "name": "neck", "tube": [[0.5, 0.25, 0.6], [0.5, 0.15, 0.8]], "bones": 2, "parent": ["spine", 2] },
      { "name": "leg_front.L", "tip": [0.75, 0.28, 0.0], "bones": 3, "ik": true, "parent": ["spine", 2] },
      { "name": "leg_hind.L", "tip": [0.72, 0.72, 0.0], "bones": 3, "ik": true, "parent": ["spine", 0] }
    ],
    "envelope": "full",
    "rigid_pieces": 0.12
  },
  "budget": 2500,
  "clips": { "archetype": "walker", "display": "Wolf" }
}

The Core Rigging Rules (A to F)

Simple bone heat skinning often fails on complex sculpts—teeth stretch across jaws, armpits glue together, and fingers merge with thighs. Autorig Workbench applies 6 procedural rules automatically during every rig build:

Rule A: Head to Snout & Articulated Jaw
A forward-facing head bone is procedurally extended forward along its axis to the anterior tip of the snout. If head_line is defined, the spine is cleanly cut at the base of the skull. If jaw is specified (with hinge point and tip), all geometry beneath the mouth plane ahead of the hinge moves from the skull to the jaw bone, blended smoothly at the lips.
Rule B: Torso Envelope & Capsule Radii
Torso vertices are projected onto the spine and partitioned along bisecting joint planes. Limbs are assigned strictly within measured 3D capsules (radius determined by limb_radius). Spikes, horns, and claws ride only the nearest bone of their parent chain. This guarantees a foreleg will never steal skin weight from the ribs or belly!
Rule C: Limbs Anchored from Body Surface
Tip-based limbs start at base coordinates on the actual body surface. For loose pieces (e.g. an arm sculpted as a detached mesh), the limb originates precisely where the piece emerges from the torso. Clavicles and scapulae are blended as girdles.
Rule D: Canonical Suffixes & Centerline Reservation
Bones situated on or near the central symmetry plane ($X=0.5$) receive un-suffixed names (spine_1, neck, tail_2). Lateral bones receive canonical .L and .R tags. root is reserved strictly for the world root bone.
Rule E: 4 Influences & Seam Integrity
Game engine GPU shaders require $\le 4$ bone weights per vertex. Decimation clamps influences to 4 and normalizes. Crucially, vertices on intentionally cut seams (e.g. bat wing membranes or cloak hems) are never accidentally merged if their weights disagree across the seam.
Rule F: Mirrored Chain Symmetry
Mirrored limbs are guaranteed to have identical bone counts, hierarchy levels, and IK setups on both sides. The QA audit automatically flags a warning if asymmetrical chains are detected.
Rule G: Geodesic Crotch & Underarm Skinning Barrier
Bone heat is geometrically blind to empty air gaps between adjacent body parts. Autorig enforces an automated geodesic barrier: vertices on the left side ($X > \epsilon$) are strictly isolated from right-leg bones, and torso vertices are protected from distal forearm/hand influences in resting poses. This universally eliminates crotch stretching and underarm tear sites across all biped, quadruped, and creature models.

Troubleshooting & Rig Repairs

The QA Audit grades models as PASS, CHECK, or FAIL. Here is how to diagnose and resolve every common issue:

1. Model Faces Sideways, Upwards, or Backwards

Symptom: Limbs stick into the torso, walk clips move sideways, or the bend test render is viewed from an odd angle.

Cause: Incorrect "forward" vector in rig.json.

How to Fix:

  1. Click Survey, then click the Survey tab in the results panel.
  2. Look at the 4 Facing Views. Identify which render shows the creature's front face / nose:
    • Face in +X view → "forward": [1, 0, 0]
    • Face in -X view → "forward": [-1, 0, 0]
    • Face in +Y view → "forward": [0, 1, 0]
    • Face in -Y view → "forward": [0, -1, 0]
  3. In Edit spec (or directly in rig.json), update forward and run Rig.

2. Audit Fails with Combined or Single Bend Tears

Symptom: Audit table shows FAIL or CHECK with tearing edges, e.g. Tears combined: 18, Worst gap: 9.4%.

Cause: Adjacent geometry is being pulled apart by opposing bones, or coincident vertices were sculpted as a fused weld.

How to Fix:

  • Identify the tearing bone: Look at the Tears by bone table in the Audit tab, or click View results in 3D to see the red tear site markers.
  • Rip accidental welds: If wing tips are welded to hips or fingers to legs, add a rip rule in rig.json: 
    "rip_welds": [["wing_tip.L", "hip.L"], ["wing_tip.R", "hip.R"]]
  • Soften joint transitions: Increase joint_blend in rig.json from 0.4 to 0.55: 
    "joint_blend": 0.55
  • Reposition limb roots: In Edit spec, verify the leg or arm root is anchored cleanly inside the mesh, not floating outside the skin.

3. Weight Bleed is High (> 2.0%)

Symptom: Audit check bleed_pct is yellow or red. Vertices on the chest move when the foot twists, or teeth deform with the neck.

Cause: Loose mesh pieces (buckles, armor, buttons, fangs) were captured by the wrong bone's heat diffusion.

How to Fix:

  • Ensure torso capsule is active: Set "envelope": "full" (for creatures) or "envelope": "root" (for humanoids).
  • Lock small loose pieces: Set "rigid_pieces": 0.15 to force any disconnected piece smaller than 15% of the model to ride exactly one bone.
  • Assign pieces to bounding boxes: Use rigid_to to force any piece in a 3D box onto a specific bone: 
    "rigid_to": [
  ["head", [0.4, 0.0, 0.7], [0.6, 0.3, 1.0]]
]

4. Head Share is Too Low (< 2.5%)

Symptom: Audit warning or failure on head_pct. The head bone only controls 0.8% of the surface.

Cause: The spine or chest bone reaches too far into the skull, leaving the head bone with only the tip of the nose.

How to Fix:

  • Enable automatic snout extension: "head_to_snout": true.
  • Define an explicit head_line cutting plane between neck and skull: 
    "head_line": [[0.5, 0.25, 0.7], [0.5, 0.05, 0.75]]
  • If the model has an open mouth, add an articulated jaw hinge: 
    "jaw": { "hinge": [0.5, 0.2, 0.65], "tip": [0.5, 0.02, 0.62], "band": 0.12 }

5. When is an Audit Allowance Justified?

Some complex geometries (such as humanoids with high-poly shoulder pads or broad dragon wings) naturally exhibit a minor tear during extreme 180° overhead arm stretches. If the model looks visually clean in the 3D Viewer during real walk, run, and attack clips: 

{
  "rig": {
    "audit": {
      "combined_tears": 8,
      "bend_tears": 4
    }
  },
  "notes": {
    "rig.audit": "Shoulder stretch on extreme dual-arm overhead pose is clean and unnoticeable in gameplay animations"
  }
}

Note: The audit reason in notes["rig.audit"] is mandatory; the Workbench flags a warning if an allowance is granted without an explanation.
